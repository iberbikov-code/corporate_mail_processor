# Архитектура и матрица маршрутизации IT-обращений

## 1. Бизнес-контекст и проблематика
В рамках анализа выборки сырых данных (all_emails.txt) были выявлены ключевые проблемы текущего процесса: смешение критических алертов инфраструктуры, рутинных запросов, фишинга и поврежденных файлов (бинарные файлы, скрытые системные файлы .DS_Store). 

Базовая сортировка на «Важное» и «Входящие» не решает бизнес-задачу IT-отдела. Нами была разработана матрица маршрутизации, разделяющая потоки заявок (L1/L2/L3) для соблюдения SLA.

---

## 2. Матрица категорий (Output Directories)

* critical_incidents (Критические сбои инфраструктуры)
  * Бизнес-ценность: Экстренная маршрутизация дежурным DevOps-инженерам (L3). Позволяет немедленно реагировать на падение серверов, минуя общую очередь L1.
  * Лексические маркеры: критичный инцидент, ошибка 500, работа полностью остановлена, у всего отдела, healthcheck 3 раза подряд, disk usage >, массовый сбой, [critical].

* access_management (Управление доступами / IAM)
  * Бизнес-ценность: Выделение задач по выдаче прав. Эту категорию можно интегрировать со скриптами автоматического создания учетных записей (Identity and Access Management).
  * Лексические маркеры: нужны права, новый сотрудник, выдать доступ, подготовить рабочее место, уровень доступа, пропал доступ, пароль истекает, восстановить.

* hardware_issues (Аппаратное обеспечение)
  * Бизнес-ценность: Маршрутизация заявок выездным инженерам (Field Support). Физические поломки невозможно решить удаленно, их необходимо сразу отсекать от специалистов программной поддержки.
  * Лексические маркеры: неисправность оборудования, заявка на ремонт, гарнитура, сканер, принтер, ноутбук, мышь, сломался экран, издаёт посторонние звуки.

* hr_finance_docs (Нецелевой документооборот)
  * Бизнес-ценность: Автоматический форвардинг счетов, актов и больничных в Бухгалтерию/HR. Снимает непрофильную нагрузку с IT-специалистов.
  * Лексические маркеры: закрывающие документы, счёт на оплату, акт за оказанные услуги, больничный лист, период нетрудоспособности, заявка на отпуск, финальная версия: договор.

* security_phishing (Угрозы ИБ и Спам)
  * Бизнес-ценность: Изоляция писем с социальной инженерией для передачи в отдел Информационной Безопасности (SecOps).
  * Лексические маркеры: выиграли iphone, введите данные банковской карты, срочно подтвердите личность, эксклюзивная акция, подозрительный вход.

## 3. Обработка аномалий и отказоустойчивость (Quarantine)
Для защиты классификатора от падения и предотвращения потери данных введена директория quarantine/unclassified. Файл маршрутизируется в карантин при выполнении любого из условий:
1. Техническая аномалия: Файл не является текстовым (.bin, .jpeg, .json, .DS_Store). Копируется "как есть" без попытки парсинга.
2. Out of Scope (Нулевое совпадение): Письмо успешно прочитано, но алгоритм не нашел ни одного зарегистрированного маркера.

---

## 4. Масштабируемость (Устойчивость к новым типам обращений)
Система спроектирована по принципу Feedback Loop (Непрерывное улучшение) и поддерживает Zero-code конфигурацию. 

Вместо жесткого кодирования (hardcode) словарей внутри Python-скрипта, все лексические маркеры вынесены в отдельный конфигурационный файл (config.json / config.yaml). Если аналитик L2 замечает в папке unclassified новый тип массовых обращений, он может добавить новые маркеры в конфигурацию за пару минут. Это позволяет системе адаптироваться к бизнес-изменениям "на лету", без привлечения разработчиков и переписывания исходного кода ядра.
